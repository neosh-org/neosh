# v0.5.1 — another computer's conversation looks exactly like it does there

A conversation opened from another paired computer now shows what that computer shows, and so do its rows in the project panel.

**The transcript is the same one.** A turn you watch from its start now ends with the rows it ends with on its own machine: the plan, what it changed, what it left running, and how long each call took. Before, those vanished at the end of every turn. A conversation you open in the middle of a turn shows the turn so far, with the other machine's clock, where before you saw only the question until the turn finished. After a dropped connection it picks up where things stand instead of spinning forever. A very long conversation no longer knocks the link over when you open it; the middles of long outputs are trimmed first. A provider error over there is shown here with the machine's name.

**Pictures cross, both ways.** A screenshot in the other machine's conversation, whether pasted there or read by its agent, is drawn here instead of showing its file name. A picture you paste into a remote conversation goes with your message. The other machine only ever sends pictures its conversation shows, never any other file.

**The rows say what they say there.** A remote conversation that finished while nobody was looking turns amber, one waiting on a question shows `?`, and a cut-off or still-running one shows `✗` or `○`, exactly as yours do. Folded projects count them. A project's git stats and its pull request badge are the other machine's own (`↓3 ~1 #86 ✗2`), read with its `git` and `gh`, including for repositories you have not cloned here. Opening a conversation from any machine marks it read everywhere. A remote turn that finishes while nobody is watching, or stops to ask you something, is now a notification here.

Also: `/update` in a development build now says what the newest release is instead of claiming to be it.

Both computers need 0.5.1. An older machine on the other end keeps working as it did in 0.5.0. After upgrading, run `neosh stop` and start `neosh` again on each machine: a running workspace keeps executing the old binary.
